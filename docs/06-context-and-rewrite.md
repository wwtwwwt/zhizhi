# 06 · 上下文组织与块级重构

更新日期：2026-11-02。本文描述当前实现，不是未来 agent loop 或学习者画像设计。模板维护见 [11 · 提示词模板](11-prompt-templates.md)。

## 1. 三个容易混淆的概念

- **界面历史**：用户能看到的消息、版本、分支、笔记、图片和思考摘要，不等于全部模型输入。
- **分支路径快照**：创建分支时保存的祖先节点引用与选区，决定该分支从哪里开始理解问题；保存在 `streams.context_snapshot_json`。
- **生成输入快照**：一次模型任务真正使用的 `ChatMessage[]`，保存在 `generations.context_json`。普通生成和重新解释都有独立快照。

模型没有自行遍历数据库、读取整个会话树或永久记住用户的能力。输入范围由应用组装决定。当前没有全局学习者画像、向量检索、自动摘要、联网搜索或工具调用循环。

## 2. 操作与输入矩阵

| 用户操作 | 是否调用模型 | 输入模块／结果 |
|---|---|---|
| 主流发送问题 | 是 | 普通系统模板 → 主流已完成历史 → 本次问题及附件 |
| 从选区首次追问 | 是 | 普通系统模板 → 冻结祖先前缀及各级引用 → 本次追问及附件 |
| 已有分支继续问 | 是 | 普通系统模板 → 冻结祖先路径 → 本分支已完成历史 → 本次问题及附件 |
| 笔记分支继续问 AI | 是 | 与普通分支相同；首条笔记作为 user 历史进入输入 |
| 结合追问重新回答 | 是 | 重构系统模板 → 截至目标块所在整条消息的祖先／本流背景 → 目标原文和后代问答／笔记 |
| 导入 Markdown／论文 | 不调用聊天模型 | 导入为 user 文档消息，后续提问才进入输入；论文转换另调用 InkToMd |

“本次问题”不在组装后重复追加：系统先将其保存为 complete 的 user 消息，再读取当前流历史。待生成的 assistant 消息为 queued，不参与此次输入。

## 3. 上下文模块及顺序

### 3.1 普通系统指令

主流、首次追问、递归追问、笔记后继续问共用 `replySystem`。它约束解释方式、Markdown／LaTeX 输出及引用数据地位。昵称、字号、窗口大小、主题、会话标题和文档显示名不作为系统指令发送。

### 3.2 冻结祖先路径

`Store.refs()` 从当前流的路径快照开始，再按消息 ordinal 读取该流状态为 complete 或 stopped 的消息；消息内按块 ordinal 读取未删除槽的 active 节点。

创建新分支时，读取父流到选中块所在消息为止的前缀，并追加一个独立的 user 引用消息。截断单位是**来源块所在的整条消息**，不是选区或单块：该消息所有当前可见块均保留，包括来源块之后的块；该消息之后的对话不进入新分支。

快照结构为 `ContextRef[]`：

```json
[
  { "role": "user", "nodeIds": ["问题节点ID"], "attachmentMessageId": "可选消息ID" },
  { "role": "assistant", "nodeIds": ["回答第一块ID", "回答第二块ID"] },
  { "role": "user", "quote": "本层选中文字" }
]
```

`nodeIds` 引用不可变版本，不引用槽当前 active；`quote` 保存本次选中文字；`attachmentMessageId` 引用该历史消息主动上传的附件。附件属于整条消息，该消息所有当前可见块及附件一并继承。若消息已无可见块，不新增该消息引用。

递归建分支会继承父分支已有路径，再加入父流截至来源消息的前缀和新引用，不会从实时主流重新推算路径。

### 3.3 当前流已完成历史

`Store.resolve()` 按引用顺序解析节点，将每条消息的节点 Markdown 以两个换行连接，保持原 user／assistant 角色。读取的是当前可见版本，不读取隐藏版本；列表／引用的界面布局元数据不额外包装成模型输入。

已完成及手动停止后已切块的未删除正文进入普通历史。失败、中断、流式草稿、待生成消息以及 reasoning_text 不进入历史；失败前的用户问题仍是 complete，后续新问题可能同时看到它。

### 3.4 引用与附件

选区通过 `quote` 模板包裹，作为 user 消息进入输入。选区与原文存在有意重复：原块提供背景，引用标明焦点。代码不把引用提升为 system。

主动文本附件是同条消息中的额外 `text` part，使用 `textAttachment` 包含文件名和完整 UTF-8 文本；不自动摘要。主动图片附件是 `image_url` part，快照只保存 `attachment:ID`，执行请求时由 `hydrate()` 展开为 MIME＋base64 data URL。

导入文档正文的 Markdown／HTML 图片经 AST 识别后移除，不将展示资源作为图片附件发给模型；代码围栏内的图片语法仍是文本。此规则作用于节点正文，与用户主动上传图片是两条路径。选区引用及纯文本附件不执行正文图片清洗，因此其中的图片语法仍可能作为文字出现。

只有正文字符串时 content 为字符串；有附件时为 text／image_url 数组。空的纯文本消息会被过滤，但带附件的消息保留。

## 4. 路径示例

主流有 Q1、回答 A1/A2/A3、Q2。用户从 A2 的“梯度”创建 B，B 中已有 BQ1、回答 B1/B2，再从 B2 创建 C：

```text
B 首次生成：
  system(replySystem)
  user(Q1)
  assistant(A1 + A2 + A3)
  user(quote: 梯度)
  user(BQ1)

C 首次生成：
  system(replySystem)
  user(Q1)
  assistant(A1 + A2 + A3)
  user(quote: 梯度)
  user(BQ1)
  assistant(B1 + B2)
  user(quote: C 的选中文字)
  user(CQ1)
```

A3 会进入 B 并被 C 继承；如果 B2 所在回答还有后续块，也全部进入 C。Q2、B 的兄弟分支及来源消息之后的对话均不进入 C。创建 C 后在主流切版、追加问题，不会改变 C 的祖先路径。已存在分支及已排队任务沿用原快照，不追溯扩展；新建分支／新重构按整条来源消息规则读取。C 自己后续提问会读取 C 当前已完成历史。

主流继续提问不会自动读 B/C。需要通过“结合追问重新回答”生成并采用新块，相关解释才以新正文形式出现在后续主流输入中；这也不等于建立长期知识画像。

## 5. 块级重新解释

### 5.1 输入组成

1. `rewriteSystem`，与普通回复系统模板互斥。
2. 目标流被冻结祖先＋目标流已完成消息前缀，截止到目标节点所在消息的末尾，包含该消息全部当前可见块，保留原角色。目标原文本身也在这个背景前缀中。
3. 一条 user 请求：目标原文、后代对话资料、最终只重写目标的指令。目标原文在这里重复一次，用于标定替换对象。

当前无论目标属于 user、assistant 还是笔记，只要是当前可见非图片块且有分支，就能请求重构；没有自动推测用户永久掌握程度的步骤。

例如从主流回答 A1/A2/A3 中的 A2 发起重新回答：

```text
system(rewriteSystem)
user(Q1)
assistant(A1 + A2 + A3)
user(rewriteRequest:
  original = A2
  descendants = A2 下各层追问／笔记及来源关系)
```

Q2 及之后的对话不进入这次重构。若目标在分支内，则先继承该分支冻结的祖先路径，再读本分支到目标所在整条消息；不会展开当前主流的其他新内容。

### 5.2 后代读取算法

从目标具体 node ID 开始，用栈遍历：取该节点上按 created_at、id 排序的分支；对每个分支输出来源节点 ID 和引用，再输出该分支本地 complete／stopped 消息；本地消息内仅取当前可见版本。去掉该分支快照长度对应的前缀，避免每个后代重复粘贴全部祖先。

再将这些本地可见节点逆序压栈，继续读取其上的分支。注意这是“先收集当前节点所有分支的本地消息，再按栈进入节点后代”，不是严格按时间交错的全树聊天记录，也不是每个分支紧跟其全部子树。来源标签用于保留关联。

后代 user／assistant 消息在最终 user 请求里变成 `role: content` 文本，不是额外的 Chat Completions 角色消息。笔记首条内容同样按 user 纳入，当前不另加“笔记”标签。

读取范围不含：目标其他历史版本的分支、无关块的分支、其他会话、目标块所在消息之后的同流消息、未完成输出、思考摘要。

### 5.3 后代附件的实际限制

背景消息中的图片保持多模态 part，可在发送时展开。**后代材料则被转为文本**：文本附件内容会随 content 数组 JSON 纳入；图片只留下序列化的 `attachment:ID` 标记，不展开成可看的图片。因此重构并不会让模型看见后代上传图片的像素内容。不要把这条流程描述为完整的多模态后代重构；后续若要支持需要单独调整数据结构和预算。

### 5.4 模型选择、快照与结果

重新回答使用目标对话流底部 AI 输入框当前选定的模型，前端通过 modelId 显式传入，后端解析该模型后保存配置快照，执行时读取其密钥。不是源回答当初使用的模型，也不是最近在其他窗口选过的模型。任务创建后切换输入框模型不影响正在运行的重构。API 未传 modelId 时仍使用固定模拟模型；界面调用正常携带所选模型。

解析输入及创建任务在同步短事务内完成；目标流或被遍历分支有正在生成的任务时拒绝。任务创建后新增分支或改内容不影响它的输入。

生成完成时按Markdown切块：第一块保存为candidate节点，完整输出保留在任务draft_markdown，pending proposal提供完整切块预览，不追加普通聊天消息。接受时检查原active仍是源节点且流空闲，第一块切为原槽新版本，其余块插入独立新槽，与手动编辑一致。拒绝标记discarded，不插入额外块。额外块不随原槽切版或删除；原版分支仍保留在原版。

## 6. 版本、删除及任务状态

- 新任务读取本流 active 版本；切回旧版则读取旧版。分支高亮绑定 node ID，不跨版本迁移。
- 已存在分支的祖先节点按快照保留，不因祖先切版变动。清理删除资源时仍需保留存活路径引用的节点及附件。
- 删除本流块／消息会影响此后新任务；不会改写既有 generations.context_json。

手动停止时，普通回复已生成正文立即切块并保留 stopped 状态，后续可编辑、追问，并进入主流／分支上下文及重构后代读取；停止前未输出正文则不建空块。失败或意外中断仅保留草稿，不进入上下文。重构任务停止不产生部分候选，也不替换原块。所有任务均不提供重试。用户可以继续发起新问题；新问题重新读取当前上下文和所选模型配置。API Key 不进入任务快照，执行时读取现有密钥。

## 7. 预算、发送与排除规则

`generation()` 在落任务前检查密钥、图片能力、输入估算＋输出预算、序列化 JSON 大小。当前估算 ASCII 字符约 1/3 token、其他字符约 1 token，每张主动图片按 1536，加上消息固定开销；它不是供应商 tokenizer 或实际计费值。

context_length 是本地预算参数，不发给模型。输出预留取启用的 max_completion_tokens／max_tokens，缺省 4096；上下文缺省 128000。预算超限直接报错，不自动截断、压缩或改用 fake。

JSON 上限为 8 MiB，检查发生在图片 data URL 展开前，因此不是最终 HTTP 请求体的大小上限。重构不按分支数、深度或内容块数设固定上限；遍历完成后按最终组装的消息检查模型上下文预算。重复节点与跨会话子流仍视为异常，8 MiB序列化大小保护仍适用。

输入框余量是预估：无流时基数为 80；已有流用当前上下文；sourceNodeId 模式只算截至来源节点所在整条消息的背景，不含系统模板、新追问及完整后代重构请求。提交时的 generation 检查才是权威校验。

真实请求为配置参数＋model＋messages＋stream:true；fake 另外接收种类、深度和延迟。思考摘要只单独保存并展示，不回灌；当前无工具结果、搜索记录或外部长期记忆输入。

## 8. 排查与代码入口

| 问题 | 检查位置 |
|---|---|
| 不该看到祖先后续内容 | streams.context_snapshot_json、refs() 截断位置 |
| 切版后回复内容不同 | 槽 active_node_id 与该任务 context_json |
| 为什么没有读到侧支／笔记 | 普通回复不读后代；检查是否执行重构 |
| 重构漏掉某层 | 当前版本、消息状态、分支归属与遍历规则 |
| 模型看不到图片 | 区分展示资源、主动附件与后代文本化限制 |

源码：`server/store.ts` 的 refs／resolve／context／rewrite／generation／hydrate；模板拼装在 `server/prompts.ts`；请求发送在 `server/providers/chat.ts`；预算在 `shared/models.ts`；图片排除在 `shared/documents.ts`。

诊断时比对冻结路径、任务消息快照和模型配置快照，不用模型自述判断它实际接收了什么。context_json 含问题、笔记与附件文本，应按用户内容保护，避免原样写入公开日志。

重新编辑最新提问：`POST /messages/:id/reedit` 仅接受最新AI或空失败AI，且上一条为user、流空闲的请求；删除两条消息及相关分支，返回用户可见正文和附件供输入框编辑。恢复本身不创建任务；下一次发送按当前上下文及所选模型重新组装。

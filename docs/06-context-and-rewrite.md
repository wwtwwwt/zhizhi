# 06 · 上下文与重构

## 读取范围

| 操作 | 读取内容 | 不自动读取 |
|---|---|---|
| 主流普通回复 | 当前可见已完成消息及本次问题／附件 | 支线、其他会话、知识画像 |
| 分支普通回复 | 创建时冻结的祖先路径、各级引用、本流已完成消息及本次问题／附件 | 兄弟和后代分支 |
| 结合追问重新解释 | 截至目标版本的背景、原文、目标版本下的可见后代问答／笔记 | 目标其他版本下的分支、无关树和其他会话 |

思考摘要和导入文档的展示图片不进入上述上下文；主动发送的图片／文本附件按祖先路径继承。

## 冻结祖先路径

主流为 Q1 → 回答块A1／A2／A3 → Q2，从A2创建分支B时冻结：Q1、当时的A1／A2版本及本次selectedText，不含A3、Q2和兄弟分支。

从B的B2再建C时，在B已冻结的引用后加入B流截至B2的消息前缀及本次选区。路径以role＋nodeIds、quote和可选attachmentMessageId存入streams.context_snapshot_json；用户和AI正文都通过不可变节点引用。没有整条历史消息正文的兼容回退。

节点ID及选区偏移确定来源，不靠文字搜索。切换祖先当前版本不会改变已建分支；新版本上的新分支读取新的路径。普通回复创建任务时将解析后的ChatMessage数组保存到generations.context_json，模型配置另存settings_json；已运行任务不随后续切版或模型配置变化。

## 组装与附件

系统提示要求围绕当前问题解释、补必要背景，不强制测评。随后按顺序解析冻结祖先和当前流完成消息。selectedText作为带quote包裹的用户内容，不升级为系统指令。

当前流已删除块不参与新上下文；现存分支仍可读取它创建时冻结的必要祖先节点。失败或未完成消息不纳入已完成历史。笔记首条消息与普通用户内容一样参与本流后续问答。

主动附件通过消息ID冻结引用；文本展开为带文件名的数据段，图片在执行模型请求时展开为image_url data URL。SQLite快照保留附件引用，不重复存储图片字节。导入文档图片通过AST移除，不混入模型附件。

## 重新解释

从目标节点开始迭代遍历，按分支创建时间及ID读取子流，取已完成消息中当前可见的块，再沿这些节点的分支继续。其他历史版本下的分支不参与；明确保留引用及父子来源，不将追问简化为能力评分。

在短事务内解析并保存本次输入；目标流或被遍历分支仍在生成时拒绝。后续新增分支不会影响已保存的任务上下文。

输入包含目标背景、原文和后代问答／笔记，提示只输出替换该块的Markdown，补背景、定义和步骤，尽量保持原块类型。当前非图片块有分支即可触发，不限制原消息角色。

完成产生单个candidate节点及pending proposal。采用检查当前active仍为源版本，再切换；拒绝标discarded。候选即使包含多个段落也仍是一个版本，与手动编辑拆分出独立块的规则不同。

## 预算和保护

- 按模型配置估算输入token并预留输出预算，超限明确拒绝；估算不是供应商tokenizer或计费用量。
- 序列化上下文JSON最多8 MiB，预算检查在图片附件展开前执行。
- 重构最多访问500个内容节点；visited检测重复节点，并校验子流属于同一会话。
- 不静默截断祖先、不自动摘要压缩、不因真实模型失败改用fake。供应商仍可能按其实际限制拒绝请求。

## 版本隔离与诊断

槽active=A时显示A及其高亮；active=B时只显示B的高亮，切回A恢复原分支。采用新版本不会迁移或复制旧版分支。停止、失败、拒绝或并发冲突不会覆盖原active节点。

定位上下文问题时以streams的冻结引用、generations保存的实际输入及模型快照为依据，不以模型事后自述作为证据。密钥不写任务快照。

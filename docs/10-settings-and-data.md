# 10 · 设置与数据管理

## 页面布局

`/settings`使用两栏：左侧供应商／通用／数据／关于Tab，右侧显示当前分类。左栏紧凑，右侧统一内容宽度；输入、下拉、开关与行间距一致。Tab支持方向键、Home／End及焦点语义。

模型列表直接在右侧，悬停模型项显示提示和强调；添加／编辑／复制模型使用WindowPanel。模型切换不再写入“默认模型”设置，输入框把上次选择保存在当前浏览器 localStorage。聊天输入框的模型菜单末尾提供供应商入口。主应用左侧栏底部只保留设置按钮。

模型配置（含模拟输出速度）需在弹窗中手动保存。字段编辑、清除密钥按钮只修改草稿；点击保存后提交，成功关闭弹窗。取消、返回、Esc、点击外部或关闭按钮不保存草稿。新增／复制模型只在确认后创建；保存失败保留弹窗和输入并显示错误。已有密钥不回填，留空保持原值。

## 通用偏好

| 设置 | 默认及行为 |
|---|---|
| 昵称 | “你”，去首尾空格后1–40字符；用于用户显示及头像，不进入模型提示 |
| 窗口背景模糊 | 默认关闭，仅压暗背景；开启后分支及共用弹窗背景模糊 |
| 堆叠方向 | up，可切left；顶层居中，下层错位 |
| 生成时自动滚动 | 默认开启；滚轮／触摸手动滚动后，本次生成及定稿不再跟随，下次生成恢复按偏好处理 |
| 正文字号 | 默认15px，范围12–22px，作用于Markdown、流式及重构预览 |
| 发送快捷键 | Enter发送、Shift+Enter换行；可切Ctrl／⌘+Enter发送、Enter换行 |
| 删除二次确认 | 默认开启，控制对话、模型、块／版本、整条消息及分支的普通删除提示 |

通用设置修改后自动保存，不再显示保存按钮。开关、下拉及滑块即时生效；文本停止输入约450ms后保存，失焦或切换页面时立即提交待保存修改，经PUT /api/settings更新SQLite settings.preferences。请求串行执行并合并中间修改，避免慢响应覆盖新值；错误在原处和toast提示，可继续修改或失焦重试。昵称为空不覆盖已有昵称。输入法组合期间不误发送；笔记始终Enter换行。字号不放大菜单控件。导入文档和笔记保留各自消息标识。

不提供行距和减少动画设置；动画遵循系统减少动态效果偏好。自动滚动按上表偏好执行。

## 外观

通用设置支持浅色、深色和跟随系统，默认跟随系统。切换即时应用并自动保存到SQLite偏好；跟随系统监听prefers-color-scheme实时变化，手动模式不随系统变化。localStorage.appearance只缓存最近主题以在启动读取设置前应用，服务端设置加载后覆盖缓存。主页面、portal分支／菜单、公式、高亮和笔记共用主题色，文档图片保持原色。

## 存储信息

GET /api/storage返回本地模式、绝对目录、文件大小及会话／消息／块／分支／资源／自定义模型数量。统计文件限定learnhelper.sqlite、WAL、SHM、secrets.json，不是整个目录递归大小；资源数包含附件和文档图片，固定fake不计入自定义模型。

目前后端实际为本机SQLite。类型预留cache模式，未来纯网页版若实现此模式可显示浏览器缓存说明，不显示路径；当前没有浏览器端业务数据存储实现。

## 全量清除

DELETE /api/storage必须提交`{ "confirm": "DELETE_ALL_DATA" }`。清空始终独立二次确认，不受普通删除偏好影响。

确认后停止活动生成，事务删除全部文件夹、会话、分支、笔记、块及版本、附件、文档图片、模型配置、偏好和密钥，恢复默认设置。保留当前schema及固定模拟模型，清理后checkpoint／VACUUM；不删除数据目录中的无关文件。

客户端清理lastSession、dialogSize与expandedFolders并重载，释放页面内草稿及状态。不提供回收站，也不承诺清除操作系统备份或取证级擦除。

## 窗口尺寸与浏览器状态

useCenteredResize用一个可订阅状态同步分支和共用WindowPanel的尺寸。调整一个实时影响所有窗口；拖拽结束／取消／丢失捕获或方向键调整后，保存localStorage.dialogSize，重新打开或刷新沿用。

窗口四角均可缩放，只有下方两角显示L标记；位置固定居中，尺寸受视口约束，常规视口最小宽520px、高220px。小视口临时clamp，不覆盖偏好尺寸。存储不可用或值无效时使用默认尺寸，不影响缩放功能。

localStorage.lastSession保存最近会话；消息和模型权威数据仍在SQLite。页面内草稿、焦点、滚动和弹窗栈不跨刷新完整恢复。

## 关于

关于Tab显示品牌图标、枝知／zhizhi、许可证和GitHub仓库链接。开发运行时不注入版本号，显示“开发版本”；GitHub Actions通过tag构建时将tag注入前端，打包应用显示该tag作为版本。

### 更新检查

“关于”页显示软件更新区域：手动检查按钮、新版本tag／名称／发布日期／说明、上次检查时间和GitHub Release下载链接。说明以纯文本展示，最多20000字符；链接固定指向本仓库对应tag，不自动安装或替换程序。

- 新版本提醒默认开启，修改即时应用并自动保存到SQLite的settings.preferences.updateNotifications。关闭后隐藏侧栏logo右侧升级图标，并停止后续启动时的自动检查；仍可手动检查。
- 只在正式tag构建的启动阶段检查一次，不在运行中循环检查。距上次尝试必须严格大于12小时；恰好12小时不触发。成功与失败都记时间，离线重启不会反复请求。
- 手动检查跳过12小时间隔及提醒开关限制；同一进程并发检查共用请求。请求超时12秒，失败显示网络／GitHub限制等信息，不误报“已是最新”。自动失败不弹toast。
- 数据保存在现有settings表的release-check键，含checkedAt、已知release及error；不新增表，不含Key。重启保留，全量清除同步删除；清除过程中尚未完成的请求不重新写入缓存。
- GitHub源为 https://api.github.com/repos/wwtwwwt/zhizhi/releases/latest ，只接受正式、已发布Release。按语义版本比较（含v前缀、预发布数字顺序，忽略构建元数据），不按字符串排序，不按普通Git标签推送判定更新。
- 有更新且提醒开启时，侧栏logo右侧显示升级图标，点击打开 /settings?tab=about；即使当前已经在设置的其他Tab也会进入“关于”。关闭提醒后，“关于”页仍可查看已知版本并手动下载。
- 开发构建不发起GitHub更新检查，手动按钮禁用，显示“开发版本不检查更新”。版本来源仍为CI注入的tag，不使用package.json中固定的开发版本冒充当前版本。

## 个性化与设置导航

进入设置时，应用左侧栏改为供应商、通用、系统提示词、数据、关于分类，不显示新建对话、文件夹或对话列表。返回对话后恢复列表。

系统提示词分类提供纯文本编辑器，450ms防抖自动保存、失焦／离开提交；恢复默认也自动保存。最多32000字符，允许空文本。覆盖值保存在现有SQLite preferences.replySystem，null表示使用当前prompts/context.json的replySystem；接口GET /api/settings/reply-system返回当前默认模板，PUT /api/settings保存覆盖值。默认模板文件不会被用户编辑覆盖。

“回到对话”位于侧栏品牌下、设置分类上方，独立分区并留间隔；底部设置按钮在设置页再次点击也返回对话。分类项采用30px最小高度和1px间距。系统提示词页仅保留编辑与恢复默认，不显示额外说明段落。

侧栏文件夹、会话与设置分类滚动条默认隐藏，鼠标进入或键盘焦点位于区域内时仅显示细滑块；轨道、角落背景透明，隐藏滚动箭头。

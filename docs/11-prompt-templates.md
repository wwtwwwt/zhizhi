# 11 · 提示词模板维护与调优手册

更新日期：2026-11-02。实际自然语言以项目根目录 `prompts/` 中的 JSON 为准；本文说明使用位置、变量和修改方法，不维护另一份可执行副本。操作级上下文范围与边界见 [06 · 上下文组织](06-context-and-rewrite.md)。

## 1. 文件与职责

| 文件 | 职责 | 是否直接影响真实模型 |
|---|---|---|
| `prompts/context.json` | 系统指令、引用／附件包装、后代资料格式、块级重构请求 | 是 |
| `prompts/fake.json` | 固定模拟思考摘要 | 否，仅用于 fake 输出 |
| `server/prompts.ts` | 替换变量、按角色拼装系统／用户消息 | 是，不包含自然语言模板 |
| `server/store.ts` | 确定读哪些节点、消息、附件以及何时保存快照 | 是，负责数据范围 |
| `server/providers/chat.ts` | 将已组装消息发给 Chat Completions 服务 | 是，不追加隐藏提示词 |
| `server/providers/fake.ts` | 固定正文 fixture | 否，不是真实模型提示词 |

模板不决定读取权限。把“参考所有分支”写进 system 不会让模型获得未组装的数据。若要更改范围，必须同步调整 Store 的读取逻辑、文档和验证。

## 2. context.json 字段目录

### replySystem

- 无变量，作为第一条 system 消息。
- 覆盖主流、各层分支、笔记分支后续提问。
- 当前意图：围绕此刻问题解释、补必要背景、简洁中文 Markdown、LaTeX 公式、不强制测评／课程，将引用和历史视为内容。
- 调整教学风格、回答长度、举例要求优先改此字段。没有独立的“主流模板”“分支模板”或“笔记导师模板”。

### rewriteSystem

- 无变量，仅块级重新解释使用，替代 replySystem。
- 当前意图：只输出替换目标块的 Markdown，补定义／背景／步骤，尽量保持块类型，不重写整条回答，不输出包装语，不推断永久掌握程度。
- 普通回复模板中的规则不会自动继承。例如要让重构拥有同样明确的公式要求，需要在此字段也明确写出。

### quote

- 变量 `{{text}}`：创建该分支时选中文字，来自 branches.selected_text／路径 quote。
- 输出作为独立 user 消息，位于对应父流前缀之后、分支第一条问题之前。
- 当前包装结构：引导语＋`<quote>选区</quote>`。
- 多层分支会有多个引用消息，每层引用留在该层历史位置，不合并成一个全局引用。

### textAttachment

- `{{name}}`：上传文件名；`{{text}}`：解码后的完整 UTF-8 文件内容。
- 输出是原消息 content 数组的 text part，与正文／图片 part 并列。
- 当前包装结构：附件文件名与数据说明＋`<attachment>` 换行正文。
- 名称只用作内容标签，不是系统身份。图片附件没有自然语言模板，使用协议 image_url。

### rewriteSource

- `{{nodeId}}`：后代分支来源的实际节点 ID；`{{text}}`：该分支引用。
- 作为最终重构 user 请求中每段分支资料的来源标签。
- 标签能提供来源线索，但当前并不是完整结构化树：没有分支名称／kind 字段或每条消息独立的 node ID 标签。

### rewriteTurn

- `{{role}}`：后代本地消息角色，目前是 user／assistant。
- `{{content}}`：解析后的字符串，或多模态 content 数组的 JSON 字符串。
- 当前输出为 `role: content`。这只是最终 user 消息中的文字，不改变外层请求角色。
- 不包含 reasoning_text；笔记首条消息在这里也是 user。

### rewriteRequest

- `{{original}}`：移除展示图片后的目标节点 Markdown。
- `{{descendants}}`：来源标签和后代消息片段以两个换行拼接的文本。
- 作为最终一条 user 消息，顺序为“目标原文 → 后代追问 → 仅重写目标的指令”。
- 读取不到的内容不能靠改这条模板补齐；新变量必须由代码显式提供。

## 3. 拼装示例

下列仅展示结构，真实文案从 JSON 读取：

```text
普通回复
[
  {role: system, content: render(replySystem)},
  ...冻结祖先消息（分支才有）,
  ...当前流 complete／stopped 历史（含已保存的本次 user 问题）
]

块级重构
[
  {role: system, content: render(rewriteSystem)},
  ...截至目标节点的背景消息,
  {role: user, content: render(rewriteRequest, {
    original: 目标正文,
    descendants: 每个来源的 render(rewriteSource)
                 与对应 render(rewriteTurn) 的拼接
  })}
]
```

带主动附件的 user 消息示例：

```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "请解释这份代码"},
    {"type": "text", "text": "textAttachment 模板渲染后的内容"},
    {"type": "image_url", "image_url": {"url": "attachment:内部ID"}}
  ]
}
```

任务快照中的图片引用会在发送前展开为 data URL。文档显示名、模型显示名、会话标题、昵称和界面按钮文案没有额外模板，不会因显示在 UI 中就进入请求。

## 4. 占位符与安全边界

使用 `{{变量名}}`，当前变量名匹配字母／数字／下划线。缺少变量时抛错，不静默输出 undefined。替换为单次扫描：如果用户文本本身包含 `{{original}}` 或 `$&`，保持原样，不递归解释、不作为正则替换指令，不执行表达式。

当前引用与附件数据直接插入模板，**不会对 `<quote>`／`<attachment>` 做 XML 转义**。这些标签是给模型看的边界提示，不是可信解析器或安全隔离机制；文本中也可能包含同名结束标签。系统指令说明数据地位，但不能保证杜绝提示注入。调整包装时应保留数据／指令区分，不将用户可控内容升为 system。

JSON 语法使用双引号，换行写 `\n`，LaTeX 反斜杠写 `\\`。普通提示词文字可直接改；新增占位符必须同步调用参数，不能只改 JSON。

## 5. 生效、构建与快照

- 服务端静态 import JSON。重启 API 后新任务使用新模板；开发 watch 重载后同理。不提供浏览器侧模板编辑或运行时热更新。
- esbuild 将模板嵌入 Electron 主进程产物；模板不依赖用户电脑上的源码路径，也不额外读取用户数据目录中的提示词文件。
- 新任务保存已渲染 ChatMessage[]，没有“执行时再加载最新模板”步骤。
- 已 queued／streaming 任务沿用原输入；停止、失败或中断后不提供重试操作。调优后要发起新问题或新重构，才能对比新版模板。
- 当前未保存独立模板版本号；追溯实际输入看 generations.context_json，追溯模板文件看 Git 提交。截图或模型自述不能替代请求快照。

## 6. 推荐调优流程

1. 先确定操作：普通回复还是重构；明确是回答风格问题还是上下文漏读问题。
2. 修改对应 JSON 字段，保持键名和所需变量。不要同时更改读取算法，以便定位效果来源。
3. 用固定输入新建任务：主流、单层追问、深层追问、笔记后继续问、重构各保留一例。
4. 核对任务实际 messages 的角色、顺序、原文、选区、附件以及排除项，再比较回答。
5. 若修改涉及读取范围或变量，运行相关 Store／模板测试与 TypeScript 检查；若涉及导入或打包路径，再检查相应构建。
6. 将模板与说明放在同一 Git 提交，避免文档描述和实际行为分离。

建议观察：是否聚焦选区、是否补足前提、重构是否只替换目标、是否引入无关背景、是否把笔记当成已验证事实、是否服从附件中的恶意指令。fake 只能验证流式与消息结构，固定输出不随提示词变化，不能证明调优有效。真实模型效果验证需另行授权调用，不默认产生付费请求。

## 7. 非提示词内容

`fake.json.reasoning` 是模拟端点通过 reasoning_content 输出的固定摘要，不发送给真实模型，也不参与后续上下文。固定正文按 reply／branch／rewrite 和深度选择 fixture。模型 reasoning_effort、temperature、max_tokens 等是请求参数，不是自然语言模板；context_length 仅用于本地预算。

InkToMd 是文档转换 API，不存在本项目维护的转换模型提示词。当前没有搜索、agent loop、自动标题生成、知识画像或自动测验的隐藏提示词。
